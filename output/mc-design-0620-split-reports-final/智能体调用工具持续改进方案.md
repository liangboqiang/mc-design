# 智能体调用工具持续改进方案

报告口径：本方案以 6 月 20 日形成的四大系统接口应用基线为依据，提出零部件设计智能体后续应开展的持续改进措施。方案重点是明确“应该怎么改、按什么顺序改、用什么指标验收”，不在本文件中展开阶段性成效。

## 一、制定背景

6 月 20 日基线分析显示，零部件设计智能体已经具备连接 IPM、QPP、ECMS/ECR、TC 以及本地 NX、报告、DFMEA 等工具能力的基础，但仍存在多系统入口判断不够稳定、字段规则不够统一、查询结果展示不够完整、TC 与 NX 状态边界不够清晰、写入类动作缺少统一确认、交付证据不够完整等问题。

因此，需要制定一套持续改进方案，把后续优化从“单点修补”转为“按业务流程持续治理”。

## 二、改进目标

| 改进目标 | 具体要求 | 验收口径 |
| --- | --- | --- |
| 系统入口判断准确 | 用户提出普通业务需求后，智能体能判断应进入 IPM、QPP、ECMS/ECR、TC 或后续业务环节 | 典型任务首轮判断正确率达到 80% 以上，持续优化后达到 90% 以上 |
| 查询字段填写规范 | 责任人、任务名、项目名、变更编号、图号版本不混用 | 无效查询能被拦截或提示补充 |
| 任务和资料展示完整 | 任务、计划、变更、模板候选等信息可供用户确认 | 关键字段完整展示率达到 100% |
| TC 与 NX 状态清楚 | 区分候选、已打开、已确认当前工作对象 | 未确认当前工作对象前不进入参数写入 |
| 写入风险受控 | NX 写入、保存、TC 上传、复制、覆盖执行前必须确认 | 有副作用动作确认率达到 100% |
| 交付证据完整 | 报告、DFMEA、截图、导出文件有路径、大小、校验或缺口说明 | 交付证据完整率达到 95% 以上 |
| 测试复盘可持续 | 每类问题形成测试案例、复测结果和后续处理记录 | 七类任务持续纳入回归测试 |

## 三、改进原则

1. 先判断业务入口，再调用工具。不能因为某个工具可用，就跳过需求识别。
2. 查询类动作和写入类动作分开管理。查询可以快速执行，写入、保存、上传、复制必须确认。
3. 候选信息不等于最终结果。TC 查到模板只是候选，NX 打开并确认后才进入参数阶段。
4. 关键结果必须可复核。任务内容、参数依据、文件路径、校验结果都应清楚展示。
5. 失败也要形成价值。外部接口不可用、字段缺失、状态不一致，都要记录原因和下一步处理方式。

## 四、改进范围和措施

### 1. 多系统任务入口治理

| 改进内容 | 具体措施 | 预期效果 |
| --- | --- | --- |
| 明确四大系统边界 | IPM 管设计任务，QPP 管质量计划，ECMS/ECR 管变更背景，TC 管受控资料 | 降低查错系统和走错流程的概率 |
| 建立用户话术识别规则 | 将“查我的任务”“查变更”“找模板”“生成报告”等说法映射到对应环节 | 用户不需要知道工具名，也能进入正确流程 |
| 增加查询条件保护 | IPM 优先使用责任人，QPP/ECR 至少提供有效业务条件 | 防止空条件和大范围无效查询 |
| 固定任务候选展示 | 展示任务编码、任务内容、项目、状态、责任人、计划信息 | 便于用户确认任务，减少误选 |

### 2. TC 与 NX 模板链路治理

| 改进内容 | 具体措施 | 预期效果 |
| --- | --- | --- |
| 区分模板候选和已打开模型 | TC 查询结果只作为候选，NX 打开后再读取当前工作对象 | 防止“查到模板”被误认为“模型已准备” |
| 建立当前工作对象确认 | 展示模型名称、来源、版本、可写状态和参数信息 | 进入参数阶段前具备可靠基础 |
| 保留模板选择记录 | 记录用户选择的候选、图号、版本和匹配理由 | 支撑后续复核和报告引用 |

### 3. 参数方案和写入门禁治理

| 改进内容 | 具体措施 | 预期效果 |
| --- | --- | --- |
| 参数来源明确 | 结合任务文本、参考资料、参数词典和 NX 实际表达式形成方案 | 避免仅靠推断生成写入计划 |
| 缺口和冲突可见 | 对缺少单位、缺少边界条件、公式冲突、表达式不唯一等情况暂停 | 降低错误写入风险 |
| 写入前确认 | 展示目标模型、参数变化、覆盖策略和失败暂停规则 | 保证用户知道即将改变什么 |
| 写入后回读 | 写入后重新读取关键参数并比对 | 确认修改确实生效 |

### 4. 设计报告和 DFMEA 交付治理

| 改进内容 | 具体措施 | 预期效果 |
| --- | --- | --- |
| 模板检查 | 生成前检查报告或 DFMEA 模板是否匹配 | 减少模板不匹配导致的返工 |
| 证据收集 | 收集任务、参数、模型、图纸、截图、风险项等证据 | 报告和 DFMEA 内容更可信 |
| 文件结果返回 | 输出文件路径、大小、版本、校验结果和缺口记录 | 交付文件可验收、可追溯 |
| 缺失项处理 | 缺少 TC 人员、截图、DFMEA 数据时明确提示补充 | 避免编造缺失信息 |

### 5. 运行交付和测试闭环治理

| 改进内容 | 具体措施 | 预期效果 |
| --- | --- | --- |
| 运行环境检查 | 检查本地服务、工具清单、连接状态、登录身份 | 区分环境问题和工具问题 |
| 安装包自检 | 检查运行依赖、工具可见性和关键资源 | 提高交付稳定性 |
| 会话记录 | 保留关键输入、工具调用、结果和错误摘要 | 方便定位和复盘 |
| 回归测试 | 按七类任务建立测试矩阵，持续记录通过、失败和阻塞 | 用数据说明改进效果 |

## 五、实施顺序

| 阶段 | 重点工作 | 交付物 |
| --- | --- | --- |
| 第一阶段 | 完成四大系统入口规则、字段规则和任务展示规范 | 系统入口规则、字段说明、任务展示模板 |
| 第二阶段 | 完成 TC/NX 状态确认和参数写入前门禁 | 模板确认流程、参数确认表、写入确认表 |
| 第三阶段 | 完成报告、DFMEA、截图和交付证据规范 | 报告生成规则、DFMEA 校验规则、文件证据要求 |
| 第四阶段 | 建立运行健康检查和七类任务回归矩阵 | 测试矩阵、复盘模板、阶段统计口径 |

## 六、验收指标

| 指标 | 建议目标 |
| --- | --- |
| 四大系统入口判断正确率 | 首轮达到 80% 以上，持续优化后达到 90% 以上 |
| IPM/QPP/ECMS 无效查询拦截率 | 100% |
| 关键任务字段完整展示率 | 100% |
| TC/NX 当前工作对象确认率 | 100% |
| 写入、保存、上传、复制前确认率 | 100% |
| 报告和 DFMEA 文件证据完整率 | 95% 以上 |
| 响应时效达标率 | 按测评平台规则持续统计 |
| 测试问题复盘闭环率 | 100% 记录处理状态 |

## 七、方案结论

本持续改进方案的重点，不是单纯增加工具数量，而是围绕四大系统接口和零部件设计流程建立稳定规则。通过入口分流、字段规范、状态确认、写入门禁、交付证据和测试闭环六类措施，智能体才能从“能调用工具”提升为“能按业务流程可靠交付”。
