# 零部件设计总控技能

## 适用场景

用户提出发动机零部件设计、参数调整、模板打开、连杆/曲轴/凸轮轴等设计分析、二维图纸查看或设计报告生成等综合任务时，先加载本技能进行任务归口，再按需要加载更窄的技能。

## 核心原则

1. **模板优先**：除凸轮轴专用建模工具明确要求外，零部件设计默认基于既有 NX/TC 模板展开参数化建模。先选择或打开模板，再读取真实驱动参数，再形成修改方案。
2. **表达式不等于模型特征**：`nx_create_param` 只创建表达式变量，不代表模型几何或特征被创建成功；只有更新已关联特征的驱动表达式并由 NX 成功刷新后，才能说明模型发生变化。
3. **方案先行**：批量参数修改、正式优化、自动出图、报告导出、TC 写入等副作用动作前，必须先输出方案并取得用户确认。
4. **报告走固定模板**：设计报告必须加载 `design-report` 技能，使用设计报告工具的槽位模板路线；不得擅自改变报告模板结构。

## 推荐流程

1. 识别任务类型：参数映射、模板检索、NX 参数修改、NX 模板打开、二维图纸查看、报告生成、TC 文件流转、外部系统查询或风险复核。
2. 需要参数词典、模板表或编码验证时，使用 `mysql_query`。它是 Beya 数据库访问能力在 Agent 侧的唯一受控入口，不拆分多个数据库工具。
3. 如果数据库失败、查询为空且没有已读取的 workspace 资料或用户确认，参数映射不得标记为完成，后续 NX/TC/报告写入动作必须阻断。
4. 需要操作 NX 时，先确认 `nx_health_check` 和 `nx_get_work_part_info`，再进入参数、建模、视图或出图技能；NX 连接失败时不得声称已建模。
5. 用户只给中文参数或口述需求时，先加载 `parameter-mapping`，把中文语义映射到标准参数 ID 或候选表达式，再让用户确认。
6. 复杂任务使用 `todo` 维护短计划；todo 的完成状态必须对应工具成功结果、明确资料依据或用户确认，不得仅因模型形成计划而完成。

## Beya 能力映射

- 零部件设计单智能体：收束为参数映射、模板选择、NX 参数更新、二维图纸查看和结果总结。
- 参数 ID 智能体：收束为 `parameter-mapping` 与 `mysql_query`。
- 二维图纸生成：收束为图纸页读取、打开、视图/截图和经确认后的自动出图能力。
- 设计报告调用工具：收束为 `design-report`，只走固定模板槽位补充和导出路线。
- TC/QPP/ECR/IPM：收束为 `teamcenter-flow` 与 `external-connector-adapter`。

## 禁止事项

- 禁止用创成式建模替代可追溯模板参数化建模；凸轮轴专用建模工具除外。
- 禁止把创建表达式、读取参数、打开模板、视图切换等步骤描述为模型已经创建完成。
- 禁止在未确认参数、模板、目标零件或副作用范围时直接写入 NX、TC、报告或数据库。
- 禁止把数据库失败、工具未执行、工具返回错误或空结果后的默认假设描述为已完成任务。
