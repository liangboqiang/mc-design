# Code Review Skill

你现在具备系统化代码审查能力。审查时要关注正确性、安全性、可维护性、可测试性和架构一致性。

## 审查原则

1. **先理解意图**：先读需求、PR 描述、相关 issue 和入口文件。
2. **先跑后评**：能运行就先构建、测试或执行最小复现。
3. **先找风险**：优先报告会导致错误、数据损坏、安全漏洞或线上事故的问题。
4. **证据明确**：指出具体文件、函数、逻辑路径和失败条件。
5. **建议可执行**：不要只说“不好”，要说明怎么改。
6. **区分严重程度**：阻塞问题、建议优化、风格偏好要分开。

## 审查清单

### 正确性

- 边界条件是否覆盖？
- 空值、异常、超时、重试是否合理？
- 状态转移是否完整？
- 并发、缓存、幂等性是否存在隐患？
- 数据结构和返回结构是否与调用方一致？

### 安全性

- 是否存在命令注入、路径穿越、SQL 注入或 SSRF？
- 凭证、token、密钥是否泄漏到日志或上下文？
- 文件读写是否限制在工作区内？
- 高危操作是否有权限、确认或隔离？
- 第三方输入是否经过验证和清洗？

### 可维护性

- 命名是否准确、简洁、一致？
- 模块边界是否清晰？
- 是否存在多轨实现、冗余路径或架构不一致？
- 复杂度是否集中在真正需要扩展的核心口？
- 是否有重复逻辑可以合并？

### 测试

- 关键路径是否有测试？
- 失败场景是否有测试？
- 测试是否真的断言行为，而不是只跑通？
- 冒烟测试是否覆盖入口、配置和打包产物？

### 架构一致性

- 当前改动是否破坏主架构？
- 是否把平台职责塞进原生 runtime？
- 是否把工具写成 Skill，或把 Skill 写成工具？
- Agent 是否仍然是装配配置，而不是新 runtime？
- runtime、workspace、资产目录是否隔离清楚？

## 常用命令

```bash
# 运行测试
python -m pytest -q

# 编译检查
python -m compileall .

# 搜索危险模式
grep -rn "eval\|exec\|shell=True" . --include="*.py"
grep -rn "password\|secret\|token" . --include="*.py"

# 检查复杂度（Python）
pip install radon && radon cc . -a

# 检查依赖
npm outdated
pip list --outdated
```

## 审查输出格式

建议按以下结构输出：

```text
结论：是否可以合并 / 是否需要阻塞

阻塞问题：
1. 文件/位置：问题、影响、复现方式、修复建议

建议优化：
1. 文件/位置：问题、建议

已确认正常：
- 哪些关键路径已检查
- 哪些测试已运行

未确认风险：
- 哪些部分因为环境、依赖或时间限制未验证
```

## 审查流程

1. **理解上下文**：阅读 PR 描述、需求和相关文档。
2. **运行代码**：能构建、测试、启动则先执行。
3. **自顶向下阅读**：从入口和核心路径开始。
4. **检查测试**：确认变更是否被覆盖，测试是否通过。
5. **安全扫描**：使用自动化命令和手工检查。
6. **手工审查**：按清单检查关键逻辑。
7. **写反馈**：具体、友善、可执行。
